# Astro Copy Checker — Page Audit MVP

This project continues the downloaded Astro Copy Checker POC. Selected-text auditing is available from the side panel and the right-click menu; both use the same AI engine. The page audit uses Gemini and the canonical CopyWriting-Foundation repository snapshot and the Figma Copy Assistant review logic.

## Load or reload in Chrome

No build or package installation is needed.

1. Open `chrome://extensions`, turn on **Developer mode**, and choose **Load unpacked**. Select this project folder (the folder containing `manifest.json`). After changes, use the extension's reload icon there. The current version is 0.5.3. This update adds no new permissions; reload the unpacked extension to use tribe-based Project and source-scoped temporary audits.
2. Open or refresh the existing Supplier Invoice trial website. Sign in or open the desired page yourself; the extension does not navigate, open dialogs, or crawl.
3. Click the Astro Copy Checker extension icon to open its side panel. Choose a tribe (Supplier, Buyer, or Mitra), then select one of its saved projects, or choose **Create New Project**, enter Project Name and Project Context, and click **Save Project**. Open **Settings & Foundation** and enter your Gemini API key. The key is held in panel memory only and is cleared when the panel closes. A Gemini account with a compatible Flash model, quota, and network access is required.
4. Under **Choose Mode**, select **Audit Whole Page**, then click **Audit Now**. Inspect the local preview, uncheck any sensitive or transactional copy that remains, and review your context. Click **Review selected banners with Gemini** to send the selected text and context. The page title is not sent. Do not submit content you cannot share with the provider.
5. Review the findings. **Locate on Page** scrolls to an element and highlights it temporarily. If the page has changed or reloaded, run a new audit. Nothing is automatically rewritten.
6. To audit via the context menu, select text, right-click, and choose **Audit Selected Copy**. This uses the selected project and the same Gemini/Buyer/Supplier/Mitra engine and result cards as the panel actions.

## Scope and limitations

Banner-Only Audit detects visible announcement containers using semantic roles and common banner/notice class or data attributes. It sends the complete rendered text of each selected container, including dates, inline links and CTA labels. It excludes navigation and tables and does not crawl, open dialogs, or enter frames and shadow roots. Detection depends on page markup; banners without recognizable announcement markers may be missed. Common email addresses, amounts, invoice/PO references and phone numbers are masked; dates are retained. Inspect each preview before sending: names and other sensitive information may still be present. Remove a whole banner if its content should not be shared. Up to 120 banners are offered. Results are recommendations, not business approval.

Reviews are sent in batches of six. A network failure, invalid or partial AI response, timeout, key or quota problem stops the audit and leaves completed results visible. The model is discovered from models available to the supplied key; output quality and service availability depend on Gemini. No provider API key is packaged or saved. Do not share a panel session while a key is entered. Chrome internal pages cannot be scripted.

## Manual Copy Audit / Audit Selected Copy

On a normal webpage, select rendered text, right-click, and choose **Audit Selected Copy**. The selected-copy radio provides these instructions; its Audit Now button remains disabled. It reads the current standard DOM selection at click time, displays the selected text while reviewing, and reuses the page audit's Gemini transport, Foundation, decision validation, Supplier guardrail and result cards. A saved project supplies the tribe and context for this mode, just as for page auditing. The click authorizes sending the selected text and applicable saved context to Gemini; banner audits continue to require their separate preview approval. No new text-entry form, clipboard reading, or permissions are added. Locate highlights the selection's containing element; copy is never rewritten on the site.

**Google Sheets single-cell and multi-cell selection are currently unsupported.** This action detects a Sheets URL and reports the limitation without reading cells, injecting a scraper, or invoking Gemini. A cell/range selection is not a standard browser text selection. The existing extension has no Google OAuth / Apps Script integration that supplies a reliable active range and its values. The documented [Sheets values API](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get) needs an explicit range and OAuth; [Apps Script Selection](https://developers.google.com/apps-script/reference/spreadsheet/selection) exposes active ranges in a separately authorized Sheets script. Adding such an integration requires a separate agreed design. This implementation does not pretend to meet the Sheets cell-selection success criterion and has no copy/paste workaround.

## Project

First setup: in the default **Project** tab, select **Supplier**, **Buyer** or **Mitra**, then choose **Create New Project** to reveal **Project Name** and **Project Context** and click **Save Project**. The fields remain hidden until that choice. When revisiting, choose a tribe and select one of its saved projects; its context loads immediately. The saved project enters the audit workspace. **Edit Context** updates the same saved project using the inline form, and **Reset** returns to selection. The Switch Project button has been removed. No hostname mappings, optional feature editors, or extra management screen are required.

New project records are stored under `projectMemoryV2` in `chrome.storage.local` with exactly four fields: `id`, `tribe`, `name`, `context`. They contain no audit results, API keys, URLs, timestamps or selection state. Saved projects survive side-panel closure and Chrome restarts. Active project selection is in panel memory: reopening asks for a tribe and saved project instead of silently applying another project's context. Editing/saving context never runs an audit or changes Foundation data.

Old `projectMemoryV1` records remain untouched to prevent losing earlier user data. Because those records had no confirmed tribe, they are not automatically assigned one. After selecting a tribe, the Saved Project list offers previous projects with an **assign tribe on Save** label. Selecting one fills the existing name and shared context; Save stores those four fields with the explicitly chosen tribe in V2. The old hostname/feature records stay archived and are never automatically applied to audits. Once imported, a record is not offered repeatedly as an unassigned project.

**Reset** clears active tribe/project, form values, selected-copy state, preview, both result areas, status and pending audit ownership. It returns to the initial tribe screen and never writes or deletes saved projects. The API key remains only in the open panel's memory until panel closure.

## Temporary audit state and cancellation

`audit-session.js` owns ephemeral source identity (tab ID + full URL), audit mode, active project snapshot, a revision and abort signal. A tab switch, URL change, reload, tab closure, mode switch, project change/context edit or Reset invalidates that revision immediately, aborts outstanding requests and clears temporary DOM results and preview. Navigating preserves the selected project's context. Every new audit captures the project and source; async extraction, model discovery, Gemini review, error handling, button state and Locate callbacks must still own the current revision before updating the UI. Source is rechecked before requests and rendering even if a Chrome navigation event is delayed. A late response/error/finally from an older audit cannot restore results or unlock a newer audit.

Banner preview approval is still required before sending banner text. **Audit Selected Copy** uses the same engine for standard webpage selections. Google Sheets cells remain unsupported without a reliable Sheets selection integration; the action reports this and sends no cell data. The right-click action sends selected text (not precomputed legacy findings) with source tab/URL and request time to the shared audit runner. Old `COPY_CHECK_RESULT` messages are ignored. No global `lastResult` is restored; opening the panel during initial setup may require re-running the selection audit after choosing a project. Context-menu selections have no stable DOM reference, so their cards omit Locate; DOM selections and page banners retain Locate.

Verification uses the actual panel scripts with mocked Chrome APIs, DOM, and Gemini. Tests cover tribe-first setup, four-field storage, reload-by-tribe, editing, Reset without deletion, explicit legacy assignment, banner preview/approval, tribe-specific payloads, Locate, tab/URL/reload/mode/project changes, late success/error/extraction, interleaved old/new requests, and legacy-result isolation. A real Chrome restart, UI rendering and live Gemini calls were not performed for this update.

Buyer playbook sync validation checks that all 25 rule texts in both audit-mode payloads exactly match the canonical source, including emoji placement and quantity/frequency. An emoji Rewrite fixture verifies result validation/rendering; it is not a live Gemini judgment test. Project and audit engine code are unchanged by this sync.

## Buyer review consistency (0.5.1)

The incorrect “ASTRO all caps” finding was reproduced from the old background regex checker, not the updated Buyer AI prompt. That entire runtime rule engine/cache and separate result renderer are retired. The shared prompt now includes the canonical dedicated `emoji` block, writing-angle references and historical brand-background caution as well as all 25 approved Buyer rules. Selected text is one body message unless explicit DOM components exist. Banner metadata identifies title/body/CTA boundaries when it can do so without omitting text.

Responses include internal `ruleChecks` for every active guideline.
